        MINIRETO #1
 
 Configurar el entorno de trabajo y crear el documento HTML base del sitio, comprobando en DevTools cómo se solicita y se escribre una página.

- URL: http://127.0.0.1:5500/index.html -> Es la dirección completa del recurso web.
- Protocolo: HTTP:// -> Indica el protocolo utilizado para la comunicación.
- Host: 127.0.0.1 -> Es la dirección del servidor al que se conecta el navegador.
- Puerto: 5500 -> Es el puerto por el que se accede al servidor web.
- Ruta: index.html -> Indica el recurso que se solicita al servidor.
- Metodo de petición: GET -> Indica qué operación solicita el navegador.
- Código de estado: 200 OK -> Indica el resultado de la petición HTTP.
- Código ruta erronea y que significa: 404 not found, este codigo indica que el navegador se conectó con éxito al servidor, pero este no puedo encontrar el recurso o la página web solicitada.
- Que rol cumplirá HTML ? -> Será el encargado del maquetado de la página, estructura y boceto principal.
- Que rol cumplirá CSS ? -> Será el encargado del estilado de las pagínas de nuestro proyecto
- Que rol cumplirá Java Script ? -> Aportar interactividad, dinamismo y lógica a las páginas web y aplicaciones.

        MINIRETO #2 - EL FORMULARIO DE RESERVAS

Construir un formulario completo y bien organizado, eligiendo el control más adecuado para cada dato.

    INSTRUCCIONES

- En reservas.html, dentro del contenido principal, crea una sección "Formulario de reserva" con un formulario que se envíe por el método post.
- Agrupa los campos en tres grupos con título: "Tus datos", "Tu alquiler" y "Confirmación".
- Elige el control más adecuado para cada dato del cliente (tipo de campo, lista desplegable, opciones únicas, casilla o área de texto). Justifica en la bitácora tres de tus elecciones.
- Asocia cada control con su etiqueta visible y asigna a cada uno un nombre para el envío de datos.
- Agrega el botón de envío al final del formulario.
- Prueba haciendo clic en cada etiqueta: el campo 
- Realizar push: Feat: El formulario de reservas.

    REQUISITOS

- <form> con action y method.
- <fieldset> y <legend>; <label> con for e id en el control.
- <input> de tipo text, email, tel, date, number, radio y checkbox; <select> y <option>; <textarea>.
- <button type="submit"> y atributo name en todos los controles.

    CHECKLIST

- El formulario tiene los tres grupos con su título y todos los datos solicitados por el cliente.
- Al hacer clic en cualquier etiqueta, su control recibe el foco o se selecciona.
- Las opciones de tipo de bicicleta comparten el mismo nombre y solo permiten elegir una.
- Todos los controles tienen name (verificable en DevTools).
- El formulario vive dentro de main y la estructura semántica del MiniReto 5 se mantiene.

    JUSTIFICACIÓN DE LAS ELECCIONES 

-  Número de documento (input type="text"): Elegí este tipo de campo porque, aunque el documento de identidad está compuesto principalmente por números, no representa una cantidad matemática. Utilizar text permite conservar posibles ceros iniciales y evita las restricciones propias de los campos numéricos.
- Tipo de bicicleta (input type="radio"): Utilicé botones de opción porque el cliente debe seleccionar un único tipo de bicicleta entre las alternativas disponibles: urbana, montaña o eléctrica. Los tres controles comparten el mismo atributo name, lo que permite que solamente una opción pueda permanecer seleccionada.
- Observaciones adicionales (textarea): Elegí este control porque permite al cliente escribir información adicional mediante un área de texto de varias líneas. Esto resulta útil para registrar solicitudes especiales, aclaraciones o comentarios relacionados con su reserva.
