6- Formulario de reservas

Se agregó en paginas/reservas.html la sección “Formulario de reserva”, dentro de main, con un formulario method="post" y action="#". Se conservaron la navegación y el aside de horarios de atención.

Los campos se organizaron en tres grupos: “Tus datos”, “Tu alquiler” y “Confirmación”. Cada control tiene un id, un name y una etiqueta visible asociada mediante for. Los tres tipos de bicicleta usan el mismo name (tipo_bicicleta), por lo que solo se puede seleccionar una opción.

Justificación de tres elecciones de controles:
1. Número de documento: se utiliza input type="text" y no type="number", porque el documento es un identificador, no una cantidad para hacer operaciones, y así se pueden conservar ceros iniciales.
2. Tipo de bicicleta: se utilizan botones radio porque el cliente debe elegir solo una opción entre urbana, montaña y eléctrica. Comparten el name="tipo_bicicleta".
3. Comentarios: se utiliza textarea porque permite escribir observaciones de varias líneas, a diferencia de un campo de texto de una sola línea.

También se usaron email para validar el formato del correo, tel para el celular, date para la fecha, number para la cantidad, select para el plan y el recorrido guiado, y checkbox obligatorio para aceptar las políticas. El botón final es type="submit".

7- Reservas sin errores: validación y teclado

Objetivo:
Aplicar validación nativa de HTML al formulario de reservas según las reglas de negocio del cliente y facilitar su uso con teclado.

Reglas de validación aplicadas en paginas/reservas.html:
- Nombre completo: input type="text", required y minlength="3".
- Número de documento: input type="text", required y pattern="[0-9]{6,10}". Se usa inputmode="numeric" para sugerir teclado numérico en dispositivos compatibles. El atributo title y el texto de ayuda explican que se aceptan entre 6 y 10 dígitos, sin letras.
- Correo: input type="email" y required para validar el formato.
- Celular: input type="tel", required y pattern="3[0-9]{9}". El atributo title y el texto de ayuda indican que deben ser 10 dígitos y comenzar por 3.
- Fecha del alquiler: input type="date", required, min="2026-11-01" y max="2026-12-31".
- Tipo de bicicleta: grupo de radio con name="tipo_bicicleta"; el atributo required en una opción del grupo exige que se seleccione una.
- Plan: select con required y una opción inicial vacía y deshabilitada para obligar a elegir un plan.
- Cantidad de bicicletas: input type="number", required, min="1", max="6" y step="1".
- Recorrido guiado: select con opción “Ninguno” y las tres rutas. “Ninguno” es una selección válida porque el recorrido guiado puede ser ninguno.
- Comentarios: textarea opcional con maxlength="300".
- Políticas: checkbox required.
- Se mantiene form con action="#" y method="post". El botón de envío es type="submit". Los controles conservan id, name y etiquetas asociadas mediante for.

- La especificidad se compara como (ID, clase/atributo/pseudoclase, tipo). El orden de aparición solo decide cuando la importancia y la especificidad están empatadas.

- El menú usa display: flex en fila y flex-wrap: wrap; en pantallas estrechas pasa a columna para evitar desbordamiento.
- Se mantuvieron las clases y estados del MiniReto 10.

Modelo de caja:
- content: área donde se dibuja el contenido.
- padding: espacio interior entre el contenido y el borde.
- border: borde alrededor del relleno y contenido.
- margin: espacio exterior que separa el elemento de otros elementos.
- Con box-sizing: content-box, width define solo el contenido; padding y border se suman al ancho exterior.
- Con box-sizing: border-box, width incluye contenido, padding y border; resulta más sencillo controlar el ancho final.

5. Registrar los dos valores en píxeles aquí: border-box = ______ px; content-box = ______ px. La diferencia esperada corresponde al padding horizontal y los bordes; los valores exactos dependen del ancho de ventana y de la tarjeta seleccionada.
